# Nour OS architecture

## 1. Runtime shape

Nour OS is a static site with one immersive runtime and one generated reading surface.

```text
src/data/*.js
   │
   ├── src/reading/render.js ── build ──> read.html        (no JavaScript)
   │
   └── src/app/immersive.js
          │
          ├── src/app/routes.js      canonical paths and aliases
          ├── src/app/store.js       frozen app state
          └── src/app/commands.js    window.NourOS (v1.0.0)
```

`index.html` loads `src/main.js`, which imports `src/app/immersive.js`. There is no bundler and no framework. `spatial2.html` is a hash-preserving redirect to `index.html`.

The reading page is generated by the build from the same content modules as the immersive app. This keeps project copy, journey chapters and contributions in one place without shipping a second renderer.

## 2. Content model

| Module | Responsibility |
| --- | --- |
| `src/data/projects.js` | Exactly five public projects, their overviews and process flows. |
| `src/data/journey.js` | Six career chapters, roles, milestones and direction. |
| `src/data/profile.js` | About copy used by Me and the reading page. |
| `src/data/environments.js` | Four scenes used by the immersive background. |
| `src/data/site.js` | Site title, description, links and contact copy. |

The public project shape is intentionally narrow: identity, cover, capabilities, `overview` and `flow`. The former `brief`, `system`, `demonstrations`, `visual`, `technology` and `impact` fields are not part of the production data model. Retired records are archived in `archive/data/retired-projects.json`.

## 3. Routing

`src/app/routes.js` is the only route authority.

Canonical routes:

- `/home`
- `/me`
- `/me/brain`
- `/journey` and `/journey/:chapterId`
- `/projects`, `/projects/:projectId`, `/projects/:projectId/flow` and `/projects/:projectId/flow/:nodeId`
- `/contact`
- `/read`

Legacy paths (`/about`, `/about-me`, `/professional`, `/about/professional`, `/simple`) are normalized and the URL is replaced with the canonical path. Unknown project, chapter or node IDs fail parsing and fall back to `/home` with a non-blocking message; the fallback uses `replaceState` so the browser Back button is not polluted.

Navigation uses `history.pushState` for intentional moves and `history.replaceState` for canonicalization, route repairs and transient process-step clearing. `popstate` and `hashchange` are both wired to a debounced route application so browser Back/Forward reconstructs the correct view.

Hover, focus and hover-triggered tooltips do not write to history. A process step creates a history entry only when clicked (or selected through the command API).

## 4. State and rendering

`src/app/store.js` is a small frozen store. Subscribers receive new snapshots and cannot mutate them.

`src/app/immersive.js` remains the single rendering and interaction layer. Key state includes:

- readiness and transition status;
- current route, section and home deck position;
- Me overlay open/view/chapter;
- project overlay open/id/view/node;
- contact visibility and active environment.

`publishState()` derives a snapshot from the live UI and publishes it after navigation, mode changes, chapter changes, flow-step changes and transition completion. The store is a reporting/command boundary, not a second source of truth for rendering.

## 5. Build pipeline

`scripts/build.mjs`:

1. renders `read.html` from the shared content;
2. writes the compatibility redirect, favicon, robots file and 404 page;
3. writes `sitemap.xml` for the canonical site URL (`SITE_URL`, default `https://nourchkair.com`);
4. copies an explicit allowlist into `dist/`;
5. removes build-time-only `src/reading/` from the deployed copy.

`archive/`, `tests/`, `docs/`, `scripts/` and `node_modules/` are never copied into `dist/`.

## 6. Archive boundary

`archive/` is outside production:

- `archive/workshop.html` and `archive/experiments/` preserve retired immersive experiments;
- `archive/data/` preserves retired project records;
- `archive/assets/` preserves legacy assets and project illustrations for future evidence.

Active `assets/` contains only four scenes, five covers, two portraits and five foreground masks (four landscape and one portrait).

## 7. Validation

`npm run validate` runs `scripts/build.mjs` and then 261 checks covering:

- data invariants, unique IDs and valid flow graphs;
- five projects and six chapters;
- route parsing, canonical paths and alias handling;
- generated reading-page counts and no-JavaScript requirement;
- index metadata, favicon and social preview;
- removal of legacy renderers and legacy CSS selectors;
- archive/dist separation and active-asset size;
- command API version, action discovery, context and rejection codes.

Browser-level evidence is recorded in `docs/validation.md`.

## 8. Constraints and remaining issues

- Hosting is Cloudflare Pages. Production is live at https://nourchkair.com and https://www.nourchkair.com; deployments are direct uploads from this repo with `npm run deploy`.
- The Cloudflare Pages project is `nourchkair`; the production branch is `main`.
- The command API is local and synchronous today; a future AI backend must call it rather than manipulate the DOM.
- `goBack()` delegates to browser history; direct-entry sessions with no prior entry fall back to Home.
- The social preview uses the existing About portrait. A dedicated branded social image can be added later without changing the architecture.
- `sitemap.xml` is generated for https://nourchkair.com; `SITE_URL` can override it for preview builds.
- The compatibility redirect uses JavaScript plus a visible link fallback; it is not intended as the primary entry point.
- Not every retired CSS declaration could be attributed to one removed component, but all selectors whose class names no longer exist in production sources were removed and visually regression-tested.
